# 确定性倒车泊车算法

本文讲解本项目用到的**确定性**泊车构造：只用常曲率圆弧和直线、不做搜索、可以写出闭式解的几何方法。它们在项目里承担三个角色：

1. 场景难度的标尺：车位长度、通道宽度与它们最小值的比值。
2. 阶段 1 数值规划器的独立校验（EXIT-0.8、EXIT-0.14(c)）。
3. 理解 RL 策略学到了什么的参照。

出处标记的含义同 [`vehicle-model.md`](vehicle-model.md)：`[V]` 已核实，`[C]` 基本可信，`[?]` 未核实，**[本项目]** 是本项目推导并做过机器核查的结论。车辆参数也相同：L = 2.7，f = 0.9，r = 1.1，w = 1.85，R_min = 3.946579 m，后轴参考。

## 1. 基本构件：两段反向等曲率 S 曲线

**构造**：先沿半径 R 的圆弧转过 φ，再反向打满、沿同一半径转回 φ，航向恢复原值，车辆整体横移 d。

对两段弧分别积分（第一段切线角为 u，第二段为 φ − u）：

```
横移   d = 2R (1 − cos φ)
纵向   X = 2R sin φ
消去 φ  →  X = √(4Rd − d²),   0 ≤ d ≤ 2R
```

例如 R = R_min、d = 2 m 时，X = 5.250965 m。

使用时要注意两点：

- 这是“转角可以瞬时从 +δ 跳到 −δ”的**几何下界**。如果要求以非零速度连续转向，换舵至少需要 `2δ/δ̇_max` 秒，过渡段会让路径变长。
- 但如果允许**停车原地打方向**（v = 0 时转动方向盘），空间轨迹可以完全不变。所以“有限转角速率必然更长”只在要求非零车速时成立，EXIT-1.8 的措辞应当带上这个前提。

- [本项目]：d03（13×31 网格数值积分，误差 4.2e-12 m）；`physics/parking_geometry.py` `ideal_two_arc_longitudinal_m`；EXIT-0.7。

## 2. 平行泊车：最小车位长度

### 2.1 原问题是欠定的

只给车辆参数无法得到唯一的最小车位长度，还必须给定：

- 前后车的横向位置和宽度；
- 路缘净空和交通侧边界；
- 初始横移量；
- “单次换向”指的是换挡（前进/倒车），还是转角变号。

这些量都会改变车角扫掠与障碍边缘的交点。

### 2.2 明示假设下的可解实例

在以下假设下问题可解：

- 全程倒车、转角变号一次，两段等半径 R 的圆弧；
- 路缘在 `y = 0`，终态航向为 0，终态后轴为 `(0, q + c)`（q = w/2）；
- 前后车与本车同宽，占据横向带 `[c, c + w]`。

四个车角绕第二段圆心的转动半径为（第一段圆弧左右互换）：

| 车角 | 半径 |
|---|---|
| 前右 `(L+f, −q)` | `√((L+f)² + (R+q)²)` |
| 前左 `(L+f, +q)` | `√((L+f)² + (R−q)²)` |
| 后右 `(−r, −q)` | `√(r² + (R+q)²)` |
| 后左 `(−r, +q)` | `√(r² + (R−q)²)` |

**四组净空约束**：

1. 车身落在前车横向带内的部分，纵向不超过前车端面；
2. 落在后车横向带内的部分，纵向不低于后车端面；
3. 整车始终在路缘之上；
4. 整车始终在交通侧边界之下。

前两组必须**先裁剪到障碍所在的横向带再取极值**，只看四个车角的投影是不够的。

在报告列出的充分条件下（横移 d > w、转角足够小，等等），结果是

```
S_min = r + √((L+f)² + 2Rw)
```

参考车辆在 R = R_min、d = 2.5、c = 0.2 时，S_min = 6.349985 m。

**后悬摆尾**：第二段圆弧的最低点由后右角决定，因此路缘净空必须满足

```
c ≥ √(r² + (R+q)²) − (R+q)
```

参考车辆为 0.1226 m。也就是说，c = 0 时直接沿圆弧贴路缘停入会让车尾扫过路缘。只检查前车角点得出的车位长度，会漏掉这个碰撞。

## 3. 倒车入库

### 3.1 坐标系与任务定义

```
库中线 x = 0；库口 y = 0；库内 −D_bay ≤ y ≤ 0；通道 0 ≤ y ≤ W_aisle（远侧为实墙）
|x| ≥ W_gap/2 且 y ≤ 0 的区域是实体（邻车或墙）
目标后轴位姿 (0, −3.9, +π/2)：车头朝外（nose-out）
来车沿通道以航向 0 行驶，车位在右侧
```

需要注意三点：

- **只接受 nose-out**。车头朝内的位姿 `(0, −3.9, −π/2)` 车身 footprint 完全相同，但成功判定必须拒绝它（EXIT-0.15）。否则“倒车入库”就悄悄变成了“入库”，倒车专用的 Reeds–Shepp 专家也不再是有效基线。
- **W_gap 是场景参数，不从 W_bay 推导**（假设 A27）。默认是保守墙模型 `W_gap = W_bay`；如果改用“两侧邻车居中停放”模型，`W_gap = 2·W_bay − w`，所需通道会差 0.69 m。
- 倒车右转入库时航向从 0 **逆时针**增到 +π/2，符号弄反会让所有车角标签互换。

### 3.2 单切构造（一次换挡）

**动作序列**：

1. 沿通道前进，航向 0；
2. **一段**半径为 R 的倒车圆弧，航向 0 → π/2，圆心 `(x_e + R, −u)`；
3. 沿 `x = x_e` 直线倒入库内。

**通道需求**：圆弧上离圆心最远的是前外角，半径为 `R_front_outer`，它经过自身圆弧的最高点，所以

```
W_aisle = R_front_outer − u
```

u 是圆心在库口线以下的深度。u 越大，通道越窄，但车身在库口占用的横向宽度越大。

**库口占用宽度 F(u)**：

- 右边界是内侧包络圆，半径 `R_swept_inner = R − w/2`；
- 左边界是后外角圆，半径 `R_rear_outer = √((R+w/2)² + r²)`。

能否通过库口只取决于一个不等式 `F(u) ≤ W′ = W_gap − 2c`。F 单调，可以反解出 `u*`（分上、下两个分支），再加上限 `u ≤ R_swept_inner − c`。

**参考车辆在 R = R_min 时的四个半径**：

| 半径 | 数值 |
|---|---|
| R_rear_outer | 4.994225 m |
| R_swept_inner | 3.021579 m |
| R_front_outer | 6.057415 m |
| R_front_inner | 4.699994 m |

**参考库（W_gap = 2.5，c = 0）**：`u* = 1.705515`，`W_aisle_min = 4.351900 m`。此时终点后轴位于 `x_e* = −0.2024 m`，**偏离库中线 0.20 m**，车身占 `[−1.127, 0.723]`，仍在库宽之内。

**如果要求停在库中线上**（x_e = 0，例如成功判定的横向容差很小），单弧加直退的最优解变为：

- 圆弧终点深度 `b* = √((W_gap − w)·R + q² − W_gap²/4) = 1.363232 m`；
- 所需通道 **4.694184 m**；
- 最优半径仍是 R_min，因为在约束活动的分支上通道需求随 R 严格递增。

如果再进一步要求圆弧**直接**结束在目标深度 3.9 m（中间不允许直退），所需半径会大到 24.49 m，通道 21.77 m。这在实际中没有意义，说明“一次进库”应当允许圆弧后接直退。

### 3.3 下界：静态包容

从航向 0 转到 π/2，根据连续性，车辆必须经过每一个中间航向 ψ。对每个 ψ，单独求“刚体放进（通道 ∪ 库）所需的最小通道”，再对 ψ 取最大值。这个量忽略了非完整约束，因此是**任何**操作（揉库多少次都一样）的必要条件：

```
A_static = max over ψ ∈ [0, π/2] of A(ψ)  =  3.510011 m，  在 ψ* = 53.04° 处取到
```

**与库深无关的精确条件**：

```
A_static(D) = max{ A_static(∞),  √(l² + w²) − (D_bay − c_end),  0 }
```

在 `D_bay ≥ l + c_end` 且库口不比默认更宽时，第二项至多 0.351 m，因此结果与库深无关。但对极宽的库口（`W_gap − 2c ≥ √(l² + w²)`），这个结论不成立。

**区间**：`[3.5100, 4.3519]`。下端对任何操作都成立；上端由单切构造给出，对应终点偏离中线 0.20 m。阶段 1 用 Hybrid A* 二分通道宽度，结果必须落在区间内（EXIT-0.14(c)）。如果低于 3.5100，在几何上就不可能，说明 footprint 摆错了，应先回去查 EXIT-0.10。v1.5 补充了前提：这个区间假设成功判定的横向容差不小于 0.25 m。

## 4. 与经典规划器的关系（阶段 1）

上面的构造只是固定路径族里的闭式解。阶段 1 会引入完整的规划器，它们的角色是：

| 方法 | 出处 | 在本项目中的角色 |
|---|---|---|
| Dubins 路径 | Dubins (1957), *Amer. J. Math.* 79(3) `[C]` | 只能前进的情形，用作 `d_Dubins ≥ d_RS` 的合理性锚点 |
| Reeds–Shepp 路径 | Reeds & Shepp (1990), *Pacific J. Math.* 145(2) `[V]`；LaValle §15.3 `[V]`；Sussmann & Tang (1991) `[V]` | 可前进也可倒车的最短路径族：48 个词，其中 46 个足够。用于快速接受判断，并作为倒车专家 |
| 连续曲率 RS | Fraichard & Scheuer (2004), *IEEE T-RO* 20(6) `[V]` | 处理转角速率有限的问题 |
| Hybrid A* | Dolgov 等 (2010), *IJRR* 29(5) `[V]` | 可行性 oracle（假设 A10：可行 = 在声明的网格分辨率下 Hybrid A* 能解出）；EXIT-0.8 与 0.14(c) 的数值二分 |

两条项目规则：

- RS 路径必须通过跟踪控制器**在环境里执行**，不能直接当作 (状态, 动作) 对使用（假设 A15），因为 RS 的曲率不连续，而本环境的车辆转角速率是有限的。
- 这些规划器都不规划速度，速度剖面要另外处理（`PLAN_MACRO.md` §5.1）。
